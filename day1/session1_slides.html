Session 1, The arc03 / 11
Part 01, the notebook

A notebook is a stack of cells.

You run one cell at a time with Shift and Enter. The kernel remembers everything you ran, so a variable made in one cell is still there in the next.

The last line of a cell prints on its own, no print needed.

# run me with Shift and Enter
print('Hello, Python')
x = 3
x + 4       # shows 7
Session 1, The cell04 / 11
Part 01, errors are normal

Read the last line first.

print('result is ' + 3)

TypeError: can only concatenate
str (not "int") to str

An error stops the cell and prints a traceback. The bottom line names the problem. Here you tried to glue a number onto text.

You will meet a handful of these all week. Reading them is a skill, and it is the one that makes you self-sufficient.

Part 01, three habits

Indentation, imports, the kernel.

Indentation

Python marks blocks with indentation. The block under a for or if is whatever is indented beneath it.

Imports

You bring in a library once with import, near the top, and it stays for the session.

The kernel

One shared memory across cells. Run them top to bottom. If things get tangled, restart and run again.

Session 1, Rosetta07 / 11
Part 02, the first object

Lists are R's vector.

parties = ['left', 'right', 'left']
parties[0]        # 'left', counts from 0
parties[:2]       # first two
parties.append('right')
for p in parties:
    print(p)

An ordered collection. You index from zero, slice with a colon inside the brackets, grow it with append, and loop over it with for.

A comprehension builds a new list in one line, the way sapply does in R.

Session 1, Lists08 / 11
Part 02, the object that matters most

Dictionaries are label maps.

A dictionary maps a key to a value. Every model in this workshop needs a label-to-id map, and that map is a dictionary. Learn this one well.

Keys are unique. Look one up with square brackets, loop with .items().

label_to_id = {'left': 0, 'right': 1}
label_to_id['left']     # 0
for name, i in label_to_id.items():
    print(name, i)
