Session 2, The chore02 / 10
Approach A

Character matching
with difflib.

import difflib
difflib.SequenceMatcher(
    None, a, b).ratio()
# 0.0 to 1.0, how alike two strings are

Score each messy name against every official name, keep the closest, accept it above a threshold, and send the rest to human review.

It is stdlib. No install, instant, and you can see exactly what it does.

Session 2, difflib03 / 10
Approach A, the result

Great on typos,
blind to meaning.

Formatting noise

0.94

Punctuation, a dropped The, Republic against Rep., a typo. Character similarity clears these.

Acronyms and renames

0.14

USA, UK, Burma. They share almost no letters with the official name, so a character score cannot see the link.

Overall top-1

29 / 43

Good, and honestly limited. Every miss is a matter of meaning.

No amount of tuning fixes an acronym, because the similarity is in the meaning.

Approach B

Semantic matching
with embeddings.

Turn each name into a vector with a language model, then link the names whose vectors sit closest. The model learned during pretraining that some names mean the same thing.

We use sentence-transformers, which runs on Colab with no fragile setup.

E_off = model.encode(official)
E_src = model.encode(source)
sims = E_src @ E_off.T
# pick the nearest official name

Session 2, embeddings result06 / 10
Neither wins outright

Two tools, two strengths.

  • difflib wins on formatting noise. Instant, transparent, stdlib.
  • Embeddings win on meaning. Acronyms, translations, and renames.
  • Both stumble on the two Congos and two Koreas, so a person still decides.

Good pipelines auto-accept the confident matches and route the rest to a human.
